# 用 CSS 变量搭一套自己的设计系统
- 2026 年 6 月 18 日 · 8 分钟阅读 · #CSS #设计  

刚开始写前端的时候,我的样式表里到处都是 #3b82f6 这样的颜色值。改一次主题色,得全局搜索替换几十处,还经常漏掉藏在某个角落里的那一行。  
后来我学会了把设计决策抽成变量:
```
:root {
  --color-brand: #2563eb;
  --color-bg: #faf9f7;
  --radius-md: 12px;
  --space-4: 16px;
}
```
这一步带来的好处远不止「方便换色」。当你被迫给每个值起一个名字时,你其实是在思考:这套视觉语言的规则到底是什么?

> 命名是设计的一部分,不是实现的附属品。

### 分两层:原始值与语义值
再往后一步,我会把变量分成两层。第一层是原始调色板,第二层是语义变量:
```
:root {
  /* 原始值 */
  --blue-500: #2563eb;
  --gray-50: #faf9f7;

  /* 语义值 */
  --color-bg: var(--gray-50);
  --color-accent: var(--blue-500);
}
```
这样切换主题时,你只需要重新映射第二层,组件代码一行都不用改。暗色模式、品牌换色、甚至节日限定皮肤,都变成了十几行 CSS 的事。

### 什么时候不该用变量
也别走火入魔。只出现一次、且没有复用意义的值,直接写就好。变量是用来表达「这套系统里的规则」的,不是用来给每个数字取名的。

判断标准很简单:如果这个值明天要改,我需要改几个地方?超过一个,就该抽出来。
